October Demo Day – Smarter Clients, Custom Highlights & Better Error Handling

This month's demo day focuses on user experience, data visibility, and system stability designed to help teams move faster, work smarter, and experience fewer interruptions.

October's Demo Day covered a set of updates that directly address the day-to-day friction points our customers have flagged most often: smarter client behavior that reduces repetitive steps, custom highlighting tools that make critical data stand out, and improved error handling that reduces confusion and speeds up problem resolution.

What Was Covered

Three major areas were featured: Smarter Clients (intelligent defaults and predictive behavior in both web and .NET clients), Custom Highlights (user-configurable color coding for list views), and Better Error Handling (clearer messages, guided resolution, and fewer dead ends).

Smarter Clients

The "smarter client" updates focus on reducing the number of keystrokes and clicks required for common tasks by having the system make better inferences about what you're trying to do.

Intelligent Defaults

  • Last-used values: Fields that typically have the same value for a given user now default to the last value entered — shipping method, warehouse location, sales rep, and others
  • Context-aware lookups: When searching for parts while entering a purchase order, the system filters results to the selected vendor's catalog by default — no more wading through thousands of parts to find the ones your vendor actually supplies
  • Predictive line entry: On order entry, typing the first few characters of a frequently ordered part number triggers a suggestion list ranked by order frequency for that customer
  • Smart date defaults: Due dates and ship dates now default based on the record context — vendor lead time for POs, customer terms for SO payment due dates, current schedule for work orders

Reduced Navigation

  • Related record quick-view panels: Hover over a customer, vendor, or part number on any screen to see a summary card without navigating away from your current screen
  • Recent records sidebar: A collapsible recent records panel shows your last 10 accessed records for instant return navigation
  • Cross-module drill-through: Click any document reference (PO number, order number, work order) from any screen to jump directly to that record

Custom Highlights

Custom highlights let users define color-coding rules for any list view in Rover Web — making important records visually distinct without requiring additional filtering or sorting.

How It Works

  • Define a rule based on any field in the list view: status, date, value, flag, or any combination
  • Assign a highlight color (from a standard palette or a custom hex code) to rows matching your rule
  • Apply the highlight to the entire row, a specific column, or just an icon indicator
  • Rules are applied in priority order — multiple rules can apply to the same list with clear precedence
  • Highlights can be personal (visible only to you) or shared (available to all users in your role)

Common Use Cases

  • Highlight overdue orders in red on the open order list
  • Flag items below reorder point in orange on the inventory list
  • Mark high-priority customers with a gold indicator on the customer list
  • Color-code work orders by work center for quick visual scanning on the production schedule
  • Show credit-hold customers in a distinct color on the order entry screen

Better Error Handling

One of the most consistent pieces of feedback from our customers has been about error messages — cryptic codes, incomplete information, and no guidance on how to resolve the issue. The October release significantly improves this.

What Changed

  • Plain-language error messages: Error messages now describe what went wrong in business terms, not system terms — "This customer has exceeded their credit limit" instead of "CREDIT_LIMIT_EXCEEDED: err 4422"
  • Resolution guidance: Most error messages now include a suggested next step — what to check, what to change, or who to contact
  • Context preservation: When an error occurs, the form no longer clears — your data is preserved so you can fix the issue and resubmit without re-entering everything
  • Error log access: Administrators can now view a filterable error log showing all errors encountered by all users in the past 30 days, with full context — useful for identifying systemic issues
  • Inline validation: More validations now happen as you type rather than on save — catching problems earlier in the workflow
